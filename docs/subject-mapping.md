# Academic Subject Mapping

## ISD — Information Systems Design
- Problem identification and stakeholder analysis.
- Functional and non-functional requirements.
- Role-based use cases for student, alumni, faculty, administrator and recruiter.
- System architecture and data-flow design.
- Relational entity and relationship model.
- Access, verification and privacy requirements.

## ASD — Advanced Software Development
- React component-based frontend.
- Node.js and Express REST API.
- HTTP GET, POST, PUT and PATCH/DELETE operations.
- JWT authentication and role-based middleware.
- Async/await, validation and centralized error handling.
- Environment-based deployment configuration.

## DBMS
- PostgreSQL relational schema.
- Primary keys, foreign keys, unique constraints and CHECK constraints.
- One-to-one and one-to-many relationships.
- Joins and aggregate queries for dashboard/report data.
- Parameterized SQL and indexes.
- CSV extraction for institutional alumni records.

## DE — Data Engineering
- Structured academic, career, mentorship and opportunity records.
- PostgreSQL storage for institution engagement data.
- Query-based extraction and summary metrics.
- CSV export as a downstream institutional data hand-off.
- Potential future extension: scheduled imports from institutional student/alumni systems. This prototype does not claim an automated institutional ETL integration.
